### Calibration / quality concerns

**Floor 5 (86.6% suppress).** Literal computation per spec passes 25% by ~3.5x. Decomposition:
- `not_a_claim`: 133 (classifier said "this segment isn't a claim" — filler, opinion, banter)
- `queue_dedupe`: 12 (entity overlap with prior recent claim)
- `malformed_output`: 9 (classifier returned non-JSON)
- `empty_primary_entity`: 7 (classifier said claim but no entity to retrieve on)

The dominant component is `not_a_claim`, which is a non-classification rather than a suppression of a candidate claim. For a 10-min podcast with 161 segments, having 133 non-claim segments is plausible — most utterances aren't claims. If the floor's intent was "fraction of *candidate claims* dropped before retrieval," the right denominator is 25 (passed) + 19 (queue_dedupe + empty_primary_entity) = 44, giving 19/44 = 43.2% — still over the 25% threshold but more interpretable. **Threshold likely needs recalibration for live podcast audio.**

**Floor 11 (100% external).** Hollow PASS — `sum(post_processor) = 0`, meaning LanceDB injection never surfaced cross-episode memory, despite EXCLUDE_EPISODE_ID=2284 leaving 100+ archived TWiST episodes available. With 0 internal cites, "external share" is mathematically 100% but the underlying signal is "internal archive failed entirely." Worth investigating: was the LanceDB score floor (0.45) too high for available memory hits, or did retrieval simply not find relevant archive matches for the USVC subject matter? The grep count of `[DOCKET] Top LanceDB score=` = 2 lines (only 2 cards even had LanceDB candidates above the score floor, and both were rejected for `score < 0.45` or `verdict=TRUE` gating).

**Floors 3 and 7 (unmeasurable).** The production server only logs citation *counts* (`haiku=N post_processor=M`), not the citation URLs themselves — those travel in the `card_card` WS broadcast and were not captured during this run. Two paths to fix for attempt 2:
1. Add a temporary `[DOCKET] cite_urls` log line in synthesis.ts (one-line diff) that emits the citation URL list per card. This is a code change pre-attempt-2.
2. Capture WS broadcast messages with a passive node WS client during the run (no code change). Less invasive but adds infrastructure.

## Failure modes — diagnosis for attempt 2

1. **Floor 1 (citation populate 36%)** — root cause is heavy `UNVERIFIABLE` (12 of 25). The classifier is producing claims that retrieval can't ground. Many `primaryEntity="unknown"` or vague entities ("fund", "unknown"). Levers: tighten classifier entity-extraction prompt, raise classifier confidence floor, or expand retrieval breadth.

2. **Floor 5 (suppress 86.6%)** — likely a threshold-calibration issue, not a real signal. Most podcast utterances aren't claims. Recommend re-defining the floor to count only post-classification suppressions (queue_dedupe + empty_primary_entity), excluding `not_a_claim` and `malformed_output` from the numerator.

3. **Floor 6 (9/25 TTFC violators)** — split between retrieval and synthesis dominance. Levers: parallelize Tavily query (currently broad+narrow sequential), reduce Pattern Recognizer LLM call to a single attempt instead of corrective-retry, or reduce retrieval source count so Docket has less to weigh.

4. **Methodology gaps (Floors 3, 7)** — add citation-URL log line to synthesis.ts before attempt 2. Single line; revertible.

5. **LanceDB archive failure** — investigate why no cross-episode memory surfaced. Possibly the score-floor at 0.45 is too tight for E2284's USVC subject. Worth a separate diagnostic before attempt 2.
